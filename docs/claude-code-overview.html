Splaude

Splash for Claude Code.

A fast local inference engine for Apple silicon, ready for Claude Code. Splaude is a fork of Splash with the server options Claude Code needs.

Source on GitHub Benchmark details

How it fits

Claude Code talks to Splaude over the Anthropic Messages API, with its full harness intact: the tool loop, hooks and subagents. Splaude serves the model locally. llama.cpp appears only as the yardstick for the numbers below.

Supported models

The list is short because each model is tuned individually: it comes with a small helper model that guesses the next words ahead, and GPU code written for that model's exact shape.

Each bubble's area is the model's total parameters; its solid core is the parameters active for each token. A dense model is all core. A mixture-of-experts model is a big shell around a small core: each token uses only a few experts, which is why the rest can be streamed from the SSD.

Parameter counts come from the model names and their Hugging Face model cards: Ornith-1.5-122B (a 122B mixture-of-experts model; its card gives no active count), Qwen3.8-Flash-Next (125B with 6B activated, plus a 51B n-gram embedding and a 4B MTP head), Flint (39.8B total, about 2.5B active). The Ornith card lists Qwen3.8-27B as dense; Ternary Bonsai 2 is built on it.

Each model loads in many sizes, 1-bit to 8-bit GGUF and 2-bit to 8-bit MLX, so smaller Macs can run a smaller version. Full list: models.md.

Caveats

  • The speed tests ran on Splash 1.4.0, the engine Splaude is built on; Splaude adds the server options Claude Code needs.
  • Splash ran with thinking on during the speed tests (its default then). Rates per token are comparable; total turn time with thinking off is lower.
  • One machine, one model. Splash's speedup comes from the DFlash2 draft and per-model kernels, so other models and Macs will differ.
  • Quality was not compared here. Splash's next-token agreement with llama.cpp is in performance.md.
